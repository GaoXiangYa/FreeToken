## 1. 模块职责与在系统中的位置

"支持图像输入"听起来像"把图喂给模型"，实际是一条跨阶段的流水线：

```
tokenize 期（本模块 processor）
  文本里的 <image> 占位符  →  展开成 N 个 pad token（N = 该图要占的 token 数）
                          并记录 [start,end) 跨度 + mrope 位置
        │
prefill 期（engine / scheduler）
  encoder_cache 查命中 → 未命中项编码 → 把嵌入 scatter 到 pad token 那几行
        │
前向（models/blocks.py:embed_input_ids）
  用 pad id 定位行，index_copy_ 覆盖成真正的嵌入
        │
之后 → 纯文本，与普通请求无差别
```

- **上游**：`tokenizer/tokenize.py` 在 `apply_chat_template` 之后调 `MMProcessor.apply`。
- **下游**：模型族的 `vision.py`（提供 `encode`）与 `layers` 的 `embed_input_ids`。
- **调度方**：`scheduler/mm.py` 规划"哪个 chunk 要编码哪些项、散布到哪几行"；`engine._run_mm_encoder` 执行。

**设计要点**：`MMProcessor` 是"族无关的驱动器 + 族相关的钩子"，所以 6 个族处理器每个只有 80-105 行。

## 3. 核心机制

### 3.1 pad id：为什么是 1,000,000

`mm/__init__.py:9` 的 `MM_PAD_SHIFT_VALUE = 1_000_000`：把 pad token 的 id 设成一个**远超任何词表**的值。这样：
- `embed_input_ids` 可以用"`id >= MM_PAD_SHIFT_VALUE`"一次性定位所有待替换行，不需要额外掩码；
- 任何遗漏的 pad id 在 embedding 层会**越界报错**，而不是静默取到某个真词——错误可见。

辅助函数：`mm_pad_value(placeholder)`（`:17`）由占位符 id 推出 pad id；`restore_placeholder(input_ids)`（`:12`）把 pad id 还原成族的占位符 token（用于日志/调试）；`check_mm_pad_shift()`（`:21`）启动期自检。

### 3.2 `PromptReplacement`（`processor.py:21`）

"一个占位符被替换成什么"的规格：

| 字段/方法 | 含义 |
|---|---|
| `token_ids` | 替换用的 token 序列 |
| `is_embed` | 哪些位置要放图像嵌入（None = 全部） |
| `select_token_id()` | 选出该用的那个 token id |
| `embed_spans()` | 相对于 `full` 起点的、半开的嵌入跨度列表 |

### 3.3 `MMProcessor`（`processor.py:67`）——驱动器 + 钩子

**族无关的驱动**：`apply(input_ids, media)`（`:112`）。
**族相关的钩子**（子类实现）：

| 钩子 | 行 | 契约 |
|---|---:|---|
| `process(media)` | 97 | 每张图产出一个 `MMItem`（含 `feature` 与 `hash`）；**offsets 由 apply 统一分配** |
| `prompt_replacement()` | 101 | 该图的占位符替换规格 |
| `positions(input_ids)` | 104 | `[3, L]` 的 t/h/w rope 位置 + decode delta；1-D rope 族返回 None |
| `dummy_items()` | 109 | 每种模态一个"最小可编码项"，用于启动时预热编码器 |
| `get_mm_processor_kwargs()` | 92 | 给 checkpoint processor 的关键字参数：先族对 `--mm-*` 的解读，再叠 `mm.processor_kwargs`（显式 key 优先） |
| `_image_processor()` | 83 | 惰性加载 checkpoint 的 image processor（tokenizer worker 内跨线程共享同一实例） |

`MMResult`（`:46`）：`apply` 的返回容器（`input_ids` / `mm_items` / `mrope_positions` / `mrope_delta`）。

### 3.4 `content_hash`（`processor.py:179`）
**62 位**哈希：wire 字节 + 族附加信息（例如 grid，所以转置后的同一张图会被视为不同）。这是编码缓存的键。

### 3.5 `EncoderCache`（`encoder_cache.py:22`）
按 `content_hash` 缓存编码结果，且**带引用计数**——同一张图被多个请求/多个 chunk 复用。

| 方法 | 行 | 作用 |
|---|---:|---|
| `register(hash, uid, rows)` | 28 | 在 uid 的任何 chunk 运行**之前**先占位（重复图会累加行数） |
| `has(hash)` | 35 | 是否已在缓存 |
| `put(hash, embeds)` | 39 | 写入 |
| `get_slice(hash, offset, n)` | 54 | 取一段行（分块 prefill 可能只取一部分） |
| `consume(uid, rows)` | 60 | 记账 uid 已收集的行；最后一个持有者的最后一行收完即释放条目 |
| `release(uid)` | 72 | 放弃 uid 的全部 claim（abort 路径）；无人持有的条目被释放 |
| `stats()` | 82 | 统计 |

**为什么需要引用计数**：分块 prefill 下同一张图的嵌入可能跨多个 chunk 被取；abort 也要能正确回收。

### 3.6 权重放置与预热
- `--mm-encoder-weights host`：塔的权重放主机 pinned bank，`BlockWeightStreamer` 两块两块地流式送 GPU（见 `07` §5.7）。
- 族的 `place_encoder_weights(mode)` 由 `models/blocks.py` 的 `SupportsMultimodal` 协议声明。
- `dummy_items()` 供 `engine._warmup_encoders` 在启动时把编码器烧热。

### 3.7 `MultimodalConfig`（`config.py:15`）
`--image-min-tokens` / `--image-max-tokens` / `--mm-encoder-weights` / `--mm-embed-cache-device` / `--mm-processor-kwargs` / `disabled_encoders` / `text_model_only`（`:29`）等运行时旋钮。**架构侧**（`vision_config`、mrope）不在它里面，而在 `ModelConfig`。

## 4. 媒体获取与安全（`media.py`）

| 函数 | 行 | 作用 |
|---|---:|---|
| `collect_image_refs(rendered_messages)` | 17 | 从渲染后的 messages 里**按 prompt 顺序**取出图像引用；裸的 `{"type":"image"}` 部件保留给 chat template |
| `image_reject_reason()` | 32 | 本服务能否接受图像输入；不能则返回**面向客户端的拒绝理由** |
| `_check_media_domain(url)` | 43 | 主机名必须在 `--allowed-media-domains` 里；空名单 = 任意域 |
| `_load_local_media(path)` | 59 | 读 `file://`；解析后的路径必须是 `--allowed-local-media-path` 的**严格子路径** |
| `fetch_image_bytes(refs)` | 80 | 把收集到的引用（URL / base64）按序变成原始字节 |

支持的三种输入：**http(s) URL、base64、`file://`**。

**工具结果里的图像为什么被挪走**：Anthropic `tool_result` 块、Responses `function_call_output` 里可能带图（Claude Code 的 Read、Codex 的 view_image）。但 chat 模板把 tool 消息渲染成纯文本，图像放进去会丢——所以服务端把它**挪到紧随其后的 user turn**（与 vLLM 一致）。

## 5. 族处理器全景表

| 处理器 | 行 | 服务族 | 图像 token 规则 | 预算/特殊点 |
|---|---|---|---|---|
| `DeepseekV41MMProcessor` | `deepseek_v41.py:38` | DSV4.1 | 每 42×42 像素一个 feature，另加每行一个 learned row break + 两个分隔符；checkpoint 上限 1024 总跨度 token | `image_grid()`（`:17`）算网格；`--image-max-tokens` 封顶整个跨度，最小面积 544×544 |

## 6. 关键流程逐段解析

### 6.1 tokenize 期：占位符展开
```
messages（含 image 部件）
  → media.collect_image_refs          # 取出引用，序
  → media.fetch_image_bytes           # URL/base64 → bytes（含白名单校验）
  → MMProcessor.apply(input_ids, media)
        for 每个 image:
            item, repl = self.process([img])          # 族钩子
            offset = 在 input_ids 里找占位符位置
            input_ids[offset] ← repl.token_ids        # 展开成 N 个 pad token
            mm_items.append(带 offsets 的 item)
        mrope_positions = self.positions(input_ids)   # 族钩子（1-D rope 为 None）
  → MMResult(input_ids, mm_items, mrope_positions, mrope_delta)
  → UserMsg 携带它进入 scheduler
```

### 6.2 prefill 期：编码与散布
```
scheduler._gather_multimodal / mm.plan_mm_batch
  → 算出本 chunk 的 cache-miss 项（mm_encoder_jobs）与散布计划（mm_gather_plan）
engine._run_mm_encoder(batch)（前向之前）
  → 对每个 miss item: model.encode(item)        # 族的 vision tower
  → encoder_cache.put(hash, embeds)
  → 按 plan 把嵌入行 gather 成 batch.mm_embeds / batch.mm_rows
前向内
  → embed_input_ids(embed_tokens, input_ids, batch)
       clamp pad id → index_copy_ 覆盖 batch.mm_rows 那些行
```

### 6.3 分块 prefill 下的图像
`batch.mm_block_ends`（`core.py:145`）记录"每个 token 所属图像块在哪里结束"；注意力后端对块内的行做**双向**注意力（`AttentionSpec.bidirectional_mm_blocks`）。`mm_chunk_end`（`scheduler/mm.py:19`）会把 chunk 边界拉回到图像跨度之前——**除非一张图比整个 chunk 还长**（此时只能切开，`cut_image_spans` 负责识别）。

### 6.4 前缀缓存命中时的复用
两层缓存叠加：`EncoderCache`（图像嵌入，按内容哈希）+ radix 前缀缓存（token 序列）。命中前缀时，被跳过的 pad token 行的嵌入由 `get_slice` 补齐。

### 6.5 权重放置对性能的影响
`--mm-encoder-weights host`：GPU 只驻留两块塔权重，用计算掩盖拷贝——**小图要付拷贝时间，大图能藏住**（`docs/cli.md:119`）。

## 8. 常见坑

1. **没有注册编码器的族直接 400**（`image_reject_reason`）。`/v1/stats` 的 `model.input_modalities` 就是给客户端做这个判断的。
2. **各族 token 预算单位不同**：Qwen 是像素面积，Gemma 是 soft-token 档位，DSV4.1 是"42×42 像素一个 feature + 行分隔"——不能跨族套用。
3. **pad id 必须被 embed 层 clamp**：漏掉会越界，而这个"越界"是**故意的**错误可见性设计。
4. **`EncoderCache` 必须 register-then-consume**：先占位再跑 chunk，否则重复图会被重复编码。
5. **图像不能被随意切**：`mm_chunk_end` 会把 chunk 边界拉回；只有超长图不得已才切。
6. **工具结果里的图要挪到后续 user turn**，否则模板渲染丢图。
7. **`--text-model-only` 不只是"不建塔"**：它把 VRAM 让给 KV/专家池，并拒绝所有多模态输入。
